# TenderOS: developer handover

Everything a developer needs to understand what was built, run it, test it, install it elsewhere
and extend it. Read in this order.

| Document | What it is for |
| --- | --- |
| [DEV-MANUAL.md](DEV-MANUAL.md) | The developer manual: the products, the stack, the repository map, the request flow (browser → Next.js API → FastAPI engine → HiGHS), the state model, a guide to every module with its entry points, conventions, how-tos and the environment variables |
| [DATABASE.md](DATABASE.md) | The database design: every table with its columns, keys, indexes and who writes and reads it, the ER diagram, the JSON documents stored in the jsonb columns, and what lives outside the database (generated by `tools/gen_db_doc.py` from the live schema) |
| [SCREEN-TO-DATA.md](SCREEN-TO-DATA.md) | Every calculated number on screen: where it is shown, the code that computes it, the inputs it rests on, and where it is stored (not stored / browser / saved bid / table) (generated by `tools/gen_screen_map.py`) |
| [FUNCTIONAL-TESTS.md](FUNCTIONAL-TESTS.md) | The functional test matrix: feature → unit tests, model checks (with LibreOffice recalculating the Excel), browser tests and deploy tests; how to run each level; the latest results; what is not automated |
| [CLICK-TESTS.md](CLICK-TESTS.md) | The manual click-test script for a tester, screen by screen, with the automated test that covers each case (`tests/e2e/test_click_tour.py` is the automated tour) |
| [INSTALL-ANY-CLOUD.md](INSTALL-ANY-CLOUD.md) | Installing the whole package on AWS, Azure, GCP or an on-prem VM: sizing, Docker, `.env`, DNS and TLS, firewall, start, migrations, first user, backups, updates, the enterprise bundle and patches |

Related documents elsewhere in the repository:

* `docs/ARCHITECTURE.md`: the architecture as built; `docs/enterprise/ARCHITECTURE.md`: the two-zone
  enterprise edition (intake zone with the cloud models, core zone with the bid workspace).
* `docs/enterprise/FEATURES.md` and the two workbooks beside it: the feature list with status, and
  the split of responsibilities between jouleWise and the client.
* `docs/DEMO2.md`, `docs/SECI_RTC.md`, `docs/TENDER_TO_BID.md`, `docs/TEAM.md`, `docs/MCP.md`,
  `docs/EXTRACTION.md`, `docs/DEPLOY.md`: one document per feature area, written as each was built.
* `deploy/enterprise/README.md`: signed bundles, installation and patches under the AMC.

## The test levels in one line each

| Level | Command | Runtime |
| --- | --- | --- |
| Engine and pack unit tests | `make test` | about 15 min |
| Model checks (Node; LibreOffice recalculates every Excel formula) | `make check-web` | about 10 min |
| Browser tests against a running stack | `make e2e` with `TENDEROS_URL`, `TENDEROS_DEMO=1` (and `MCP_TOKEN` for the connector test) | about 7 min, plus the sizing runs |
| Click tour (every tab, step and button, no long jobs) | `pytest -m slow tests/e2e/test_click_tour.py` with the same variables | about 3 min |
| Deploy tooling | `pytest tests/deploy` | seconds |
| Generated documents still match the code and the schema | `make docs-check` (needs `DATABASE_URL`) | seconds |
